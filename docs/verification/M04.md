## 3. Key Delivered Components

1. **Topic Architecture (`services/processor/src/topics.ts`):**
   - Declares `events.raw.v1`, `events.normalized.v1`, `incidents.v1`, `investigations.requested.v1`, `events.retry.1.v1`, `events.retry.2.v1`, and `events.dead-letter.v1`.

2. **Correlation Engine (`services/processor/src/correlation.ts`):**
   - Sliding 30-minute event-time correlation window.
   - Deterministic stable incident IDs: `INC-[SHA256(key).slice(0,8)]`.
   - Causal linking between deployments and subsequent alert spikes on the same service.

3. **Retry Strategy & Error Classification (`services/processor/src/retry-strategy.ts`):**
   - Classifies errors as `TRANSIENT` (lock timeouts, connection resets) or `PERMANENT` (schema errors, poison payloads).
   - Exponential topic retry progression: Attempt 1 -> `retry.1` (1s), Attempt 2 -> `retry.2` (2s), Attempt >= 4 -> `dead-letter`.

4. **Event Bus & Consumer Worker (`services/processor/src/queue.ts`, `worker.ts`):**
   - Manual offset commits with lag calculation.
   - At-least-once transport to exactly-once business effects via `InboxDeduplicator`.
   - DLQ replay capability for operator remediation.
