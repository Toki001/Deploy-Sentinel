## 3. Security Hardening Details

1. **Non-Root Execution in Containers**:
   - `apps/web/Dockerfile`: Runs as `USER nextjs` (uid: 1001, gid: 1001) under Next.js standalone server mode.
   - `services/api/Dockerfile`: Runs as `USER deploysentinel` (uid: 10001, gid: 10001).
   - `services/processor/Dockerfile`: Runs as `USER deploysentinel` (uid: 10001, gid: 10001).
   - `services/investigator/Dockerfile`: Runs as `USER deploysentinel` (uid: 10001, gid: 10001).

2. **Supply Chain Security & GitHub Actions**:
   - All third-party GitHub Actions are pinned to full immutable 40-character commit SHAs.
   - CI triggers check for frozen lockfiles (`pnpm install --frozen-lockfile`) to prevent untracked dependency drift.
   - Release workflow adheres to least privilege: `packages: write`, `contents: read`.

3. **Release Gate & Honest Blocker Accounting**:
   - The host system's Docker daemon is not active (`Cannot connect to the Docker daemon`). Live container builds and GHCR image pushing cannot be executed locally.
   - Workflow manifests provide dry-run safety checks if `GITHUB_TOKEN` is unavailable, marking image publication as unverified rather than fabricating a successful push.
