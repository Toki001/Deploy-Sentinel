## 3. Scenarios Evaluated

1. **5,000-Event Replay Suite (`tests/replay/event-replay.test.ts`):**
   - 4,400 valid events generated across 10 microservices, 4 event types (`DeploymentCreated`, `AlertTriggered`, `ErrorRateChanged`, `ConfigurationChanged`), with simulated clock ticks.
   - 500 duplicate events injected to verify idempotent inbox suppression.
   - 100 poison payloads (50 malformed JSON lines, 50 schema-violating objects) injected to verify deterministic DLQ routing.
   - Total execution time: ~1.2s, verifying high-throughput offline replay processing.

2. **Fault Injection & Concurrency Suite (`tests/integration/fault-injection.test.ts`):**
   - Outbox lease expiration: Leased message held for 1s, manually expired, and picked up by secondary worker failover.
   - Poison message isolation: Zod errors, malformed JSON, and explicit poison strings routed to `events.dead-letter.v1` on attempt 1 with delay 0.
   - Transient retry progression: Retried through `events.retry.1.v1` (1000ms delay), `events.retry.2.v1` (2000ms delay), up to attempt 4 then escalated to DLQ.
   - Deduplication: In-memory/transactional inbox prevents re-processing duplicate events per tenant while preserving cross-tenant autonomy.
   - Backpressure: Worker pauses consumption on signal; consumer lag accumulates; worker resumes and drains pending messages gracefully before termination.
   - Strict Multi-Tenancy: Concurrent interleaved events for `checkout-gateway` from `org-north`, `org-south`, and `org-west` are isolated into 3 distinct tenant-scoped incidents.
   - State Machine: Proves allowed transitions (`open -> acknowledged -> investigating -> mitigated -> resolved`, plus reopen `resolved -> open`). Disallowed jumps throw `BadRequestError`. Stale versions throw `ConflictError` (409).
